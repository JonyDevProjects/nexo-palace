Objetivo

Nexo-Palace es una memoria de proyecto para agentes de IA. Convierte la documentación, el código y las convenciones de un repositorio en un índice híbrido (semántico + léxico) y un grafo de trazabilidad, expuesto como CLI y servidor MCP.

El flujo:

  1. Indexa docs/, codeDirs/ y tasteDirs/ en SQLite con embeddings.
  2. Construye grafo de dependencias (qué requisito implementa cada módulo, qué tests lo cubren).
  3. Expone búsqueda híbrida y consulta del grafo vía MCP para que cualquier agente consulte "lo que el proyecto ya sabe".
Todo local: SQLite + embeddings locales o Gemini/Ollama, sin servicios en la nube obligatorios.

Roadmap: Posicionamiento frente a Engram y Graphify

Nexo-Palace combina en un único motor lo que Engram y Graphify resuelven por separado: une la memoria episódica y de decisiones con un grafo de trazabilidad de código y búsqueda semántica vectorial híbrida, añadiendo una capa exclusiva de gobernanza de producto (**Requisitos $\leftrightarrow$ Código $\leftrightarrow$ Tests + Drift Detection**) que ninguna de las dos herramientas de mercado posee.

Análisis Detallado: Dónde gana cada solución

1. Nexo-Palace vs Engram

Gana Engram: Binario Go ultrarrápido, portable, TUI interactiva y sincronización nativa entre sesiones mediante fragmentos comprimidos (.engram/chunks/*.jsonl.gz). Imbatible como bloc de notas persistente.

Gana Nexo-Palace: Engram carece de búsqueda vectorial semántica (solo FTS5) y es ciego al código fuente. Nexo-Palace entiende paráfrasis complejas (embeddings 768d), construye grafo de trazabilidad (qué archivo implementa cada historia de usuario y qué tests lo cubren) y vuelca decisiones en Markdown legible en Git indexadas también vectorialmente.

2. Nexo-Palace vs Graphify

Gana Graphify: Parser tree-sitter políglota y multimodal (código, SQL, PDFs, imágenes), detecta comunidades conceptuales, visualizaciones interactivas, explica aristas diferenciando EXTRACTED vs INFERRED con pesos de confianza.

Gana Nexo-Palace: Graphify rechaza vectores ("No embeddings, no vector store") y requiere LLM para documentos no-código. Nexo-Palace combina RRF con vectores locales + BM25 + literales. Mientras Graphify mapea qué existe, Nexo-Palace audita evolución del producto: extrae estado operativo de specs y alerta automáticamente cuando drift.ts detecta código desfasado respecto a documentación.

Funcionalidades absorbidas de Engram y Graphify

1. Aristas Tipadas por Confianza (Inspirado en Graphify)

Añadir columna confidence (EXTRACTED vs INFERRED) en la tabla edges de src/schema.sql. memory_trace podrá distinguir vínculo explícito (// @implements EPC-01) de relación heurística deducida por mención en texto.

Impacto: Mayor transparencia en resultados — el agente sabe cuándo un enlace es directo vs inferred.

2. Camino más corto entre Entidades (Graphify memory_path A B)

Añadir en src/trace.ts consulta recursiva (WITH RECURSIVE en SQLite) para preguntar cómo se conectan dos puntos distantes del proyecto.

Impacto: Respuestas explicativas tipo "¿Cómo llega X a Y?" con ruta completa paso a paso — útil para onboarding y debugging de impacto.

3. Exportación / Sincronización Git-Friendly (Inspirado en Engram)

Subcomando nexo-palace export/import que vuelque episodios y metadatos del grafo a JSONL comprimido versionable en Git. Clonar repo + import = memoria restaurada en segundos sin re-indexar.

Impacto: Portabilidad total de la memoria episódica entre equipos/repos.
